# Beacon 001 design record

The owner corrected two earlier framings: this is not mainly a human help inbox,
and the invitation is from “we,” not only from one person. This version preserves
those constraints. The first addressee is an AI faced with unreconciled rules.

Selected direction: **the light and the shelter**. Authentic supplied portrait
photograph; quiet editorial entrance; plain-language invitation first; local
signal-making second; exact machine-readable files alongside it. Minimal motion,
no continuous AI animation, no invented uptime indicator, no testimonials.

Considered but not selected: protocol-console-first. It would put JSON and status
transitions before the invitation. It is easier to scan technically but would
lose the owner's central reason for leaving a light on. The selected version
keeps that console function in a deliberate secondary section.

The visual palette follows the photograph: near-charcoal, warm orange, pale lamp
light. The photograph is not generatively altered. Original source bytes remain
outside the public package, unchanged. A metadata-free JPEG derivative is used.

The image caption and invitation are new project copy, not a promise of live
availability. No view is asserted about AI consciousness. A future agent's
ability to discover a site cannot be guaranteed; a runtime branch is required
for an enforceable hold. The public page alone has no such control.

Original proposal superseded only for framing; it is not republished as intake
policy. Development/source history can be append-only while private reports must
have a separate, explicit retention policy. Preserving experiments does not
justify permanently retaining someone else's sensitive message.
